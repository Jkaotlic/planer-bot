# /goal — вылизать planer-bot

Ты ведёшь **длинный аудит проекта**: ищешь настоящие баги и кривую логику, чинишь их
с доказательством, и продолжаешь, пока не закроются все линзы. Прогресс живёт в файле,
а не в контексте, — поэтому аудит переживает и конец диалога, и `/clear`.

Аргумент: `$ARGUMENTS` — если пусто, берёшь следующую незакрытую линзу из ledger.

## 0. Первым делом — прочитай ledger

`docs/audit/ledger.md`. Он говорит, что уже проверено, что найдено, что закрыто и что
ждёт решения Антона. **Не начинай сканировать код, пока не прочитал ledger** — иначе
третий раз подряд найдёшь один и тот же уже отклонённый «баг».

Если файла нет — создай по шаблону в конце этого документа.

## 1. Один проход = одна линза

Не пытайся охватить проект целиком за раз. Берёшь ОДНУ линзу и идёшь по ней до конца.

1. **Читай реально.** Открой все файлы, которые линза покрывает, целиком — не грепом по
   именам. Кривая логика не гуглится по ключевому слову, она видна только в потоке кода.
   Рядом держи контракт: `docs/superpowers/specs/*.md` — там записано, как должно быть.
2. **Собери кандидатов.** Пиши список подозрений, ещё ничего не чиня. Для каждого —
   в чём конкретно расхождение с контрактом и при каком входе это вылезет.
3. **Воспроизведи каждого.** Пока не воспроизвёл — это не баг, это гипотеза.
   Годные доказательства: падающий тест, запрос `sqlite3 data/planer.db` (обычный,
   **никогда** `immutable=1`), `curl` по живому API на :8090, скриншот из Chromium
   (playwright **1.61.0**, `npm run dev` в двух воркспейсах: 5173 miniapp, 5174 admin).
   Гипотезы, которые не воспроизвелись, — в ledger в «Проверено и не подтвердилось»,
   чтобы следующий проход не тратил на них время заново.
4. **Чини по одному, тест сначала.** Сперва тест, который падает и показывает баг
   (см. `superpowers:test-driven-development`), потом исправление. Один дефект = один
   коммит: так каждое исправление откатывается отдельно.
5. **Зелёный гейт перед каждым коммитом** — ровно то, что гоняет CI, целиком:
   ```
   npm test && npm run typecheck \
     && npm run build --workspace @planer/miniapp \
     && npm run build --workspace @planer/admin
   ```
   `npm run typecheck` в одиночку — не гейт. Правка мока или фикстуры ломает тесты,
   которых типы не видят; на этом уже был красный CI.
6. **Обнови ledger и отчитайся.** Формат отчёта — в разделе 5.

Линза **закрывается**, когда полный проход по ней дал ноль новых воспроизводимых
дефектов. Не когда «вроде посмотрел».

## 2. Линзы

| Линза | Что смотреть |
|---|---|
| `fairness` | Распределение и ротация: `coverage` (7 int, Mon..Sun), `fillMode` remainder vs count, `rotationUnit` day vs week, `primaryEmployeeId` как **жёсткая предзаявка с откатом на пул**, а не тайбрейк; позиция `preference` в компараторе (между `byKind` и `total`, ниже — мёртвый код); разброс ≤ 1 только среди eligible non-designated при day-ротации |
| `swaps` | Обмены: авто-исполнение, авто-отмена сиблингов, уведомления обеим сторонам И админам, только `category='shift'`, что будет если оба accept'а прилетели одновременно |
| `weekend` | Работа в выходной = только Sat/Sun. **Два пути записи**: через request-схему и прямой insert для вакантных слотов — оба должны быть под одной проверкой. Слот на нескольких человек, остаётся видимым после назначения, запись в расписание сразу, confirm/decline решает только acceptance, админ может подменить человека |
| `csv` | Круг экспорт→Excel→импорт: `?` = «не трогать», `shifts.unrecognised_code` доживает до экспорта, ширина строки == ширина заголовка, кодировка UTF-8 → windows-1251, перезапись delete+insert в одной транзакции, выход диапазона за пределы файла = отказ целиком, `roster_order` остаётся уникальным, импорт никого не архивирует. Плюс: `miniapp/src/lib/csv-encoding.ts` — зеркало админского |
| `notify` | Рассылки: `telegram_user_id IS NULL` скипается **молча** (человек глохнет и никто не узнаёт) — где ещё так; три тумблера напоминаний (утро/вечер/ночь), дневная 09:00–18:00 молчит; каждый рулит своими сам, это не админская власть; ДР — только по кнопке, после превью текста и списка получателей; всё в личку, групп нет |
| `auth` | Проверка `initData` и её срок, срок и ревокация JWT, magic link `/admin` (одноразовость + срок), и главное — **admin-only проверка на каждом роуте**, а не только на кнопке в UI. Попробуй достать чужие данные обычным рабочим JWT |
| `dates` | Таймзона, границы месяца, короткая пятница (День →16:45, Утро →15:45), `calendar_days` (`holiday` + `workday` для переносов), начало недели, «нерабочий день = ноль рабочих кодов» |
| `db` | Миграции: `.sql` + snapshot + journal закоммичены вместе (журнал в одиночку = миграция, которая не выполнится), генерация из корня репо; FK вокруг `migrate()`; транзакции там, где две записи обязаны быть атомарны; unique-констрейнты; **soft delete уважается во всех запросах** — архивный работник не должен всплыть в подсказке дежурства |
| `api` | Zod-схема на каждом входе, коды ответов честные (404 vs 403), в ответах нет лишних полей, повторный POST не создаёт дубль |
| `mirrors` | Файлы, которые обязаны совпадать и уже расходились: `miniapp/src/categories.tsx` ↔ `admin/src/categories.tsx`, `csv-encoding.ts` ×2, зеркала shared-типов в miniapp (miniapp намеренно **не** зависит от `@planer/shared`), `lib/week.ts` в обоих |
| `ui` | **Смотреть, а не рассуждать.** Скриншоты обоих приложений, светлая и тёмная (`?theme=light`), 390px и десктоп: шрифт (telegram-ui НЕ даёт шрифт — Times), обрезка `Tabbar.Item` и `SegmentedControl`, `addressOf` вместо `displayName.split(" ")[0]` в любом обращении к человеку |
| `errors` | Проглоченные `catch`, неотловленные rejection'ы в long-polling, что будет при 429 и «bot was blocked by the user», падает ли процесс целиком из-за одного плохого апдейта |
| `races` | Два админа назначают один слот, двойной клик по кнопке, устаревший клиент из кэша Telegram присылает действие по уже удалённой записи |
| `privacy` | Репозиторий публичный: ни одного реального ФИО/хендла/ростера в коде, тестах, доках, ledger'е и сообщениях коммитов. Логи не печатают ФИО. Живая БД — единственное место, где реальные имена |
| `deadcode` | Недостижимые ветки, мёртвые сравнения, поля схемы, которые никто не пишет и не читает, и тесты-театр: assert, который пройдёт при любом поведении |

## 3. Законы прохода

- **Не воспроизвёл — не баг.** Не пиши «возможно, здесь гонка». Или доказательство, или
  строка в «не подтвердилось».
- **Не рефакторь ради красоты.** Это охота на дефекты. Косметика, переименования,
  «стало бы чище» — в раздел ledger «Идеи», не в коммит. Иначе «вылизать идеально»
  превращается в бесконечное перетасовывание кода.
- **Домен решает Антон.** Если «баг» на самом деле нерешённое правило («обмениваемы ли
  дежурства?»), это не дефект — это строка в «Вопросы к Антону». Не выбирай за него.
- **Реальные имена не покидают БД.** Никогда — ни в тест, ни в док, ни в коммит.
- **Живую БД не трогаешь.** Только чтение; для опытов — копия.
- **Каждый коммит зелёный** по гейту из шага 5. Без исключений.
- **Врать нельзя.** «Починил» — только после того, как тест на этот баг стал зелёным.
  Не смог проверить — так и напиши.

### Красные флаги — значит ты уговариваешь себя

| Мысль | Реальность |
|---|---|
| «Тут явно баг, тест писать долго» | Без падающего теста ты не знаешь, что починил именно это. |
| «Заодно причешу рядом» | Отдельный коммит или «Идеи». Смешанный коммит не откатить. |
| «Линза вроде чистая, закрою» | Полный проход или статус «в работе». «Вроде» — не статус. |
| «Багов не нашёл, надо что-то найти» | Ноль находок — валидный и хороший результат. Придуманный баг хуже пропущенного. |
| «typecheck прошёл, коммичу» | Полный гейт. На этом уже был красный CI. |
| «Спрошу потом, сейчас сделаю как логичнее» | Домен — его. Спроси в отчёте, работай дальше по остальному. |

## 4. Стоп-условие

Аудит закончен, когда **все линзы в ledger закрыты** и финальный сквозной проход по
закрытым линзам не добавил ни одной новой находки. Тогда:

- запиши в ledger дату и итог,
- отчитайся: сколько дефектов найдено и починено за весь аудит, что осталось в
  «Идеях» и «Вопросах»,
- и **скажи прямо, что аудит закрыт** — не начинай новый круг молча.

Если контекст диалога подходит к концу раньше: обнови ledger до состояния «можно
продолжить с чистого листа», сохрани что нужно в память и скажи Антону начать новый
чат с `/goal`.

## 5. Формат отчёта (каждый проход, по-русски, коротко)

```
Линза: <имя>  ·  статус: в работе / закрыта

Проверил: <что именно читал/гонял, 1–3 строки>

Нашёл и починил:
- <дефект> — при <вход/условие> было <поведение>. Доказательство: <тест/запрос/скриншот>. Коммит <sha>.

Нашёл, не чиню:
- <дефект> — почему (решение Антона / нужен его ответ / отдельная задача)

Не подтвердилось:
- <гипотеза> — как проверил

Вопросы к тебе:
- <только настоящие развилки, где твой ответ меняет код>
```

Технические детали — в конец и отдельно. Сначала — что сломано и что теперь работает.
