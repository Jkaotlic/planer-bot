# План полного аудита planer-bot по линзам `/goal`

> **Для исполнителя:** это план аудита, а не фичи. Код находок заранее неизвестен —
> поэтому шаги задают, **что читать, что проверять и что считается доказательством**,
> а не готовые сниппеты. Порядок внутри прохода всегда один и тот же (см. «Ритуал
> прохода»). Отмечай `- [x]` по мере закрытия.

**Цель:** пройти все 14 незакрытых линз `/goal`, починить каждый воспроизведённый
дефект с тестом и доказательством, и довести `docs/audit/ledger.md` до состояния, где
у каждой линзы стоит «закрыта».

**Подход:** одна линза за проход, риск-первым. Проход не смешивает линзы: находка из
чужой линзы записывается в ledger и чинится в свой ход (исключение — если она в том же
файле, что уже правится, тогда отдельным коммитом).

**Стек:** TS монорепо (shared / server / miniapp / admin), vitest, drizzle+SQLite,
grammY long-polling, Hono. Живая система на этой машине: `data/planer.db`, :8090.

## Глобальные ограничения

Действуют в каждом проходе, повторять в задачах не нужно:

- **Не воспроизвёл — не баг.** Доказательство: падающий тест, запрос
  `sqlite3 data/planer.db` (обычный, **никогда** `immutable=1`), `curl`/скрипт против
  живого :8090, или скриншот из Chromium (playwright **1.61.0**).
- **Тест сначала**, потом починка. Один дефект = один коммит.
- **Гейт перед каждым коммитом, целиком:** `npm test && npm run typecheck &&
  npm run build --workspace @planer/miniapp && npm run build --workspace @planer/admin`.
- **Реальные имена не покидают живую БД** — ни в тест, ни в док, ни в коммит, ни в
  ledger. Репозиторий публичный.
- **Домен решает Антон.** Развилка правил → строка в «Вопросы к Антону», а не догадка.
- **Косметика — в «Идеи»,** не в коммит аудита.
- **Живую БД только читаем.** Опыты — на копии.
- **Сборка фронтов только с** `VITE_BOT_USERNAME=schedullerboysforrent_bot`.
- **Деплой:** правки только во фронтах → достаточно пересборки (`serveStatic` читает с
  диска). Правки в `server/` или `shared/` → нужен перезапуск демона, а он под `sudo`:
  спросить Антона (он жмёт Restart в меню-баре) и подтвердить подменой pid на :8090.
- **Перед перезапуском** — `sqlite3 data/planer.db ".backup ~/planer-pre-<тег>.db"`.

- [ ] Шаг 6. Обновить ledger, отчитаться Антону в формате из `/goal`, спросить про

## Порядок линз и почему такой

Риск считается как «сколько людей это трогает» × «узнает ли кто-нибудь, что сломалось».
Живые факты на 2026-07-30, которые задают приоритет: **19 из 28 человек без телеграма**,
`calendar_days` пуста и без читателей, пулы пусты, 1038 записей за июнь+август.

| # | Линза | Почему здесь |
| --- | --- | --- |
| 1 | notify | 19 глухих людей; молчаливый скип — известный класс дефектов в этом коде |
| 2 | auth | проверки прав; находки почти гарантированы, цена ошибки максимальная |
| 3 | db | soft delete во всех запросах, атомарность пар, миграции |
| 4 | swaps | самый используемый рабочими флоу после «мои смены» |
| 5 | weekend | два пути записи, один в обход схемы |
| 6 | races | двойные клики и устаревшие клиенты Telegram |
| 7 | errors | проглоченные catch, падение long-polling |
| 8 | api | схемы на входе, коды, лишние поля в ответах |
| 9 | dates | короткая пятница, границы месяца, праздники (см. вопрос про `calendar_days`) |
| 10 | csv | круг экспорт→Excel→импорт, уже многократно правленный |
| 11 | ui | смотреть, а не рассуждать: скриншоты обоих приложений |
| 12 | mirrors | файлы-двойники; частично начата |
| 13 | privacy | реальные имена в коде/тестах/логах |
| 14 | deadcode | мёртвые колонки и таблицы, тесты-театр |
| 15 | fairness | **холодный** закрывающий проход из нового чата |
