# `/week` — график команды на неделю картинкой

Дата: 2026-08-06 · слой 1 (сервис) · спека утверждена Антоном

## Зачем

Посмотреть график сейчас можно ровно одним способом: открыть мини-апп, дойти до
вкладки «Команда», переключиться на «Неделю». Это четыре действия ради взгляда
на сетку, которую хочется видеть так же быстро, как читаешь сообщение.

Команда `/week` присылает ту же сетку картинкой прямо в чат: команда × семь
дней, цветные клетки с буквами, легенда снизу. Один тап — и график перед
глазами, листается кнопками.

## Чего эта задача НЕ делает

**Это не страховка от падения бота.** Бот и HTTP-сервер живут в одном процессе
(`server/src/index.ts`: `bot.start()` и `serve(app.fetch)` под одним launchd-
демоном). Если процесс лёг, `/week` не дойдёт до бота ровно потому же, почему не
откроется мини-апп. Страховкой была бы картинка, которую бот шлёт **заранее**, по
расписанию, — она лежала бы в чате и читалась без сервера. Антон выбрал
удобство, не страховку; отдельный проактивный канал в эту работу не входит.

Также вне рамок: личная картинка «мои смены» (решено — только команда), кэш
готовых PNG (рендер ~50 мс, кэшировать нечего), настоящий скриншот мини-аппа
headless-браузером (см. «Отвергнутые варианты»).

## Решения Антона

1. **Команда видна всем** — `/week` попадает в меню Telegram рядом со `/start` и
   `/notifications`.
2. **На картинке вся команда × неделя + легенда** — то же, что во вкладке
   «Команда → Неделя» мини-аппа.
3. **Листание кнопками** «‹ Пред. неделя» / «След. неделя ›» под фото, бот
   перерисовывает и заменяет фото в том же сообщении.
4. **Рисуем PNG сами на сервере** (SVG чистой функцией → растеризация), а не
   снимаем скриншот браузером.

## Отвергнутые варианты

- **Headless-браузер (Playwright) снимает `/app/`.** Пиксель-в-пиксель и ноль
  дублирования вёрстки, но: ~300 МБ Chromium на мак-мини, ещё один процесс,
  умеющий зависать; авторизацию надо прокидывать внутрь страницы (initData бот
  подделать не может — пришлось бы выдавать JWT и строить механизм уровня
  `/admin`); таймауты, шрифты и гонки загрузки дают флаки, TDD там не живёт.
  Слишком дорого за удобство.
- **Текстовая табличка в `<pre>`.** Ноль зависимостей, но десять с лишним человек
  × семь дней на телефоне рассыпаются переносом строк, а цвета теряются целиком —
  остаются голые буквы, которые без легенды не читаются.

## Архитектура

Четыре слоя, каждый тестируется отдельно; ниже — что переезжает, что новое.

### 1. Модель недели переезжает в `shared/`

Сегодня «какая буква в какой клетке» знает только мини-апп
(`miniapp/src/lib/team-schedule.ts`), а цвета записей без пресета живут в
`miniapp/src/categories.tsx`. Серверу нужно то же самое, и второй реализации быть
не должно — иначе картинка и мини-апп разъедутся по буквам и цветам, причём
молча.

Переезжает в **`shared/src/week-model.ts`**:

- типы `TeamEntryView`, `WeekCell`, `WeekRow`, `WeekModel`, `WeekLegendItem`;
- функции `coversDate`, `splitDisplayName`, `compareShifts`, `toEntryView`,
  `weekCell`, `buildWeekModel`, `buildWeekLegend`.

Переезжает в новый **`shared/src/week-dates.ts`**: `toISODate`, `parseISODate`,
`addDays`, `mondayOf`, `weekdayIndex`, `weekdayShort`, `formatWeekRangeLabel`.
Отдельный модуль, а не существующий `time.ts`: тот про часы смены
(`toMinutes`, `isNightShift`, `resolveShiftTimes`), а это про календарь недели.
Добавляются строковые двойники — `mondayOfIso`, `addDaysIso`,
`formatWeekRangeLabelIso`: на сервере объект `Date` затащил бы в арифметику
часовой пояс машины вместо часового пояса команды.

Переезжает в **`shared/src/schedule-palette.ts`** (к точным палитрам):
`LIGHT_PALETTE` под именем `CATEGORY_PALETTES_LIGHT` и функция
`categoryPalette(category, isDark)`. `DARK_PALETTE` едет с ней — держать две
половины одной таблицы в разных пакетах хуже, чем перевезти обе.

**Типизация — по структурному минимуму.** Переехавшие функции описывают вход
локальными интерфейсами («что-то с `date`, `endDate`, `category`,
`templateId`…»), как уже делает `ColourableEntry` в `categories.tsx`, а не типами
`Shift`/`Template` из `miniapp/src/api/client.ts`. Тогда и строка из БД, и JSON
из API подходят без конвертации.

**Мини-апп не переписываем.** `miniapp/src/lib/team-schedule.ts` и
`miniapp/src/categories.tsx` реэкспортируют переехавшее, поэтому ни один
компонент не меняется. Зелёные тесты мини-аппа — доказательство, что переезд
ничего не сломал.

### 2. Общий шейпер расписания

`GET /api/team/schedule` (`server/src/http/app.ts`) не просто отдаёт строки: он
выкидывает смены архивных сотрудников (их нет среди строк сетки, поэтому клиенту
они уезжали только чтобы быть отброшенными) и урезает поля до безопасных — `note`
это админское поле, работникам его не видно.

Картинка обязана показывать ровно то же. Копия этой фильтрации внутри рендера
разъедется с роутом при первой же правке, поэтому логика выносится в
**`server/src/repo/team-schedule.ts`**: `readTeamSchedule(db, from, to)` →
`{ employees, shifts }`. Роут и рендер зовут её оба; роут после этого только
валидирует параметры и отдаёт результат.

### 3. Рендер: SVG чистой функцией, потом растеризация

**`server/src/render/week-svg.ts`** — `renderWeekSvg(input): string`, где
`input = { model, legend, weekLabel, today }`. Ни одной зависимости, только
конкатенация строк; вся тестируемая часть рисования — здесь.

Геометрия (px):

| Элемент | Значение |
| --- | --- |
| Ширина холста | 1200 |
| Поля слева и справа | 16 + 16 |
| Колонка фамилий | 244 |
| Колонка дня | 132 (7 × 132 = 924; 244 + 924 = 1168 = 1200 − поля) |
| Заголовок недели | 44 |
| Шапка с днями | 64 |
| Строка сотрудника | 56 |
| Строка легенды | 40, по две в ряд |
| Поля | 16 |

Высота = поля + шапка + строки + легенда. Telegram принимает фото при
`width + height ≤ 10000`, то есть до ~150 строк — упираться в это команда из
десятка человек не начнёт, отдельного ограничения не вводим.

Выходные определяются существующей `isWeekend` из `shared/src/time.ts` — в
мини-аппе для этого есть свой `isWeekendIso`, а в `TeamWeekGrid` ещё и локальный
`isWeekend`; третью копию заводить не будем.

Оформление повторяет мини-апп: выходные колонки фоном темнее, сегодняшняя
колонка с рамкой, клетка залита `palette.bg` и подписана `palette.code` цветом
`palette.fg`, вторая и далее запись в клетке сворачивается в «+N». Фамилия
берётся из `splitDisplayName` и режется по символам с «…» — в SVG нет
`text-overflow`.

**Экранирование обязательно.** Любой текст (фамилия, название пресета) проходит
через `escapeXml` для `& < > " '`. Одна фамилия с амперсандом иначе ломает весь
документ, и картинка не отрисуется ни для кого.

**`server/src/render/rasterize.ts`** — `svgToPng(svg): Buffer` на
`@resvg/resvg-js` (проверено: prebuilt `@resvg/resvg-js-darwin-arm64` есть,
компилировать нечего), с `fitTo: { mode: "width", value: 1200 }`.

**Шрифт кладём в репо.** `server/assets/fonts/` — DejaVu Sans Regular и Bold
(лицензия Bitstream Vera, разрешительная, файл лицензии рядом), ~1.4 МБ, и
`loadSystemFonts: false`. С системными шрифтами картинка зависела бы от того, что
установлено на конкретной машине, а на CI кириллица могла бы не отрисоваться
вовсе — текст просто исчез бы, и тест этого не заметил.

### 4. Сборка и команда

**`server/src/bot/week-image.ts`** — `buildWeekImage(db, mondayIso, today)`:
`readTeamSchedule` за `[monday, monday+6]` → `buildWeekModel` + `buildWeekLegend`
→ `renderWeekSvg` → `svgToPng`. Возвращает `{ png, caption }`.

Подпись: `Команда · 10–16 августа` (через `formatWeekRangeLabel`, тот же формат,
что в шапке мини-аппа). Та же строка печатается **внутри** картинки заголовком:
пересланное фото подпись сообщения теряет, и без заголовка неясно, какая это
неделя.

**`server/src/bot/bot.ts`**:

- `bot.command("week")` — гард `acting()`, понедельник текущей недели по
  `config.teamTz` (`teamNow`), `replyWithPhoto` с подписью и клавиатурой.
- `bot.callbackQuery(/^week:(-?\d+)$/)` — тот же гард, пересчёт недели,
  `editMessageMedia`.
- `publishBotCommands` += `{ command: "week", description: "График команды на неделю" }`.

**Оффсет в callback-данных абсолютный** — число недель от текущей, не от
показанной. Кнопка «‹ Пред.» на неделе `+2` несёт `week:1`. Состояния на сервере
нет, кнопка в старом сообщении через месяц отработает корректно относительно
сегодняшнего дня.

Диапазон зажат в **±26 недель**. За границей — тост «Дальше не листаю», фото не
трогаем. Когда оффсет ≠ 0, в клавиатуре появляется третья кнопка **«⌂ Текущая»**:
без неё возврат с 26-й недели это 26 тапов.

## Доступ

Гард `acting()` из `bot.ts` — тот же, что у всех остальных кнопок бота:

- не в системе → «Сначала отправь /start»;
- в архиве и не в `ADMIN_TELEGRAM_IDS` → «Ты в архиве — напиши админу».

Расширения доступа нет: `/api/team/schedule` уже отдаёт эти же данные любому
авторизованному работнику. Картинка — другой носитель тех же фактов.

Фикстуры тестов — только выдуманные имена. В репо есть
`server/src/db/no-real-names.test.ts`, и он там не случайно: настоящие имена
однажды уже утекли в публичный репозиторий.

## Ошибки

| Ситуация | Поведение |
| --- | --- |
| Растеризация бросила | Лог + «Не смог нарисовать график, открой мини-апп». Не молчим и не роняем процесс. |
| Люди есть, но за неделю ни одной записи | Рисуем сетку с пустыми клетками; вместо легенды строка «На этой неделе записей нет». |
| В ростере никого | Текстом «В расписании пока никого» — рисовать сетку без строк бессмысленно. |
| `editMessageMedia` упал при листании | Тост «Не получилось, попробуй ещё раз», прежнее фото остаётся на месте. |
| Оффсет за ±26 неделями | Тост «Дальше не листаю». |

Ошибка при листании — не косметика (в отличие от `safeEdit` в существующих
обработчиках): перерисовка фото **и есть** полезное действие, поэтому её провал
сообщается человеку тостом, а не только в лог.

## Тесты

Слой 1 — TDD обязателен, тест вперёд кода.

**Переезд в `shared/`:** тесты едут вместе с функциями. Отдельного доказательства
не требуется — зелёный набор мини-аппа после реэкспорта и есть доказательство.

**`week-svg.test.ts`** (чистая функция, самый плотный набор):

- строк ровно столько, сколько людей в модели;
- строка «Не назначено» появляется только когда в неделе есть неназначенные смены;
- клетка залита цветом пресета и подписана его буквой;
- две записи в одной клетке → рисуется «+N»;
- длинная фамилия обрезана с «…»;
- сегодняшняя колонка помечена, выходные выделены;
- пустая неделя рисует сетку и строку «На этой неделе записей нет»;
- **фамилия с `&` и `<` экранирована** — в выводе нет сырых спецсимволов.

**`rasterize.test.ts`:** на вход минимальный SVG → на выходе буфер с
PNG-сигнатурой и заявленной шириной.

**`week-image.test.ts`:** смены архивного сотрудника в картинку не попадают;
понедельник считается по `TEAM_TZ`, а не по времени машины; подпись совпадает с
ожидаемой строкой диапазона.

**Бот-тесты** в стиле существующего `server/src/bot/bot.test.ts`: без `/start` —
отказ; архивный — отказ; `/week` отвечает фото; callback с оффсетом за границей
диапазона фото не меняет; кнопка «⌂ Текущая» есть при оффсете ≠ 0 и отсутствует
на текущей неделе.

## Зависимости

Одна новая: `@resvg/resvg-js@^2.6.2` в `server/package.json` (prebuilt
`darwin-arm64`, сборка не нужна). Плюс два TTF в `server/assets/fonts/`.
