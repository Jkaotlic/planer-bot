# Stage 2B: экран «Команда» — дизайн

**Дата:** 2026-07-27
**Статус:** дизайн визуально утверждён пользователем; ожидается проверка письменной спецификации.

## 1. Цель

Переделать worker-facing экран мини-приложения «Команда» в два read-only режима:

- компактное расписание выбранного дня — **«Сегодня»**;
- цветная матрица всей команды на семь дней — **«Неделя»**.

Экран должен переносить рабочую семантику и точные цвета исходной табличной сетки, но оставаться читаемым на телефоне.

## 2. Зафиксированные решения

- При каждом новом открытии экрана выбран режим **«Сегодня»**.
- Переключение на **«Неделю»** выполняется вручную.
- Выбранный режим не сохраняется в `localStorage`, Telegram CloudStorage или на сервере.
- В обоих режимах доступны стрелки назад/вперёд:
  - «Сегодня» сдвигает выбранную дату на один день;
  - «Неделя» сдвигает диапазон на семь дней.
- При переходе из «Сегодня» в «Неделю» открывается неделя, содержащая выбранную дату.
- Неделя начинается в понедельник.

## 3. Цветовая карта

Фоны ячеек и маркеры групп используют точные оттенки, измеренные по рабочему JPG:

| Запись | Код в недельной ячейке | Фон | Текст |
|---|---:|---:|---:|
| Обычная смена (`День`) | `С` | `#EAF0F0` | `#17202A` |
| Утро | `У` | `#FEFF01` | `#17202A` |
| Вечер | `В` | `#08AFF3` | `#062C3B` |
| Ночь | `Н` | `#20497C` | `#FFFFFF` |
| Дежурство · Телефон | `Т` | `#F2B07E` | `#17202A` |
| Дежурство · Вавилова 19 | `ВА` | `#FFBE00` | `#17202A` |
| Дежурство · Поклонка | `П` | `#FE87FF` | `#39133A` |
| Дежурство с 07:00 | `07` | `#CBC04D` | `#292505` |
| Отпуск | `О` | `#FD0100` | `#FFFFFF` |

Цвет не является единственным носителем смысла: недельная ячейка всегда содержит короткий код, а подробное название доступно по нажатию.

Эта карта едина для worker mini-app и админки. Цвета смен не меняются между светлой и тёмной темами; нейтральный фон, границы и остальные поверхности остаются theme-aware.

Категории, для которых пользователь не задал рабочий оттенок (`sick_leave`, `business_trip`, `offsite`, `weekend_work`), сохраняют текущие category-палитры и полные подписи. Эта задача не придумывает им новые соответствия.

## 4. Исправление пресета 07:00

Существующий пресет `Открытие` не соответствует рабочей терминологии. Его нельзя просто удалить: на него могут ссылаться исторические записи.

Аддитивная миграция обновляет существующую строку пресета на месте:

- `name = 'Дежурство с 07:00'`;
- `category = 'duty'`;
- время остаётся `07:00–16:00`, пятница `07:00–14:45`;
- акцент остаётся тем же слотом, но его UI-цвет становится `#CBC04D`;
- `isActive = true`.

Та же миграция заменяет сохранённый `shifts.title = 'Открытие'` на `Дежурство с 07:00` для записей этого пресета. Идентификатор пресета сохраняется, поэтому исторические и будущие записи не теряют ссылку. Название и понятие `Открытие` исчезают из активного UI, mock-данных и пользовательских текстов.

## 5. Режим «Сегодня»

### 5.1 Компоновка

Верх экрана:

1. заголовок «Команда»;
2. сегментированный переключатель `Сегодня | Неделя`;
3. выбранная дата и стрелки предыдущего/следующего дня;
4. компактные счётчики «На работе» и «Отсутствует».

Основная область группирует сотрудников по виду записи. Каждая группа показывает:

- точный цвет вида смены узкой вертикальной полосой;
- полное название;
- время;
- полные ФИО всех сотрудников этой группы.

Ключ группы — `templateId`, если он есть. Для кастомной записи ключ строится из `category + title + start + end + location`, чтобы разные по смыслу смены с одинаковым временем не объединялись случайно.

### 5.2 Постоянная сортировка по времени

Timed-группы всегда сортируются по `start` по возрастанию. Для одинакового времени используется `shift_templates.sort_order`, затем название как стабильный последний tie-break.

Пример порядка: `07:00 → 08:00 → 09:00 → 11:00`.

Сотрудники внутри группы сортируются по `rosterOrder`, затем по `employee.id`.

Записи без времени (`vacation`, `sick_leave`, `business_trip`) выводятся после timed-групп в отдельном разделе **«Без времени»**. Они сортируются по категории, затем сотрудники — по порядку ростера.

Счётчик «На работе» считает уникальных сотрудников в timed-записях, «Отсутствует» — уникальных сотрудников в категориях отсутствия. Неназначенная timed-запись показывается внутри своей группы как «Не назначено», но не увеличивает счётчик сотрудников.

Если на выбранную дату записей нет, экран показывает штатное пустое состояние, но навигация по датам остаётся доступной.

## 6. Режим «Неделя»

### 6.1 Матрица

- Строки — все активные сотрудники, включая людей без записей на выбранной неделе.
- Порядок строк — `rosterOrder`, затем `employee.id`; это тот же порядок, что сохраняет импортированный ростер и CSV-экспорт.
- Столбцы — семь дней, понедельник–воскресенье.
- Вся неделя помещается в ширину телефона без горизонтального свайпа.
- Фамилия и имя показываются в две строки в закреплённой левой колонке.
- Цветные элементы имеют внутренние отступы и скругления, поэтому соседние смены не сливаются.
- Сегодняшний столбец получает акцент сверху.
- Суббота и воскресенье отделяются нейтральным фоном.
- Нажатие на заполненную ячейку открывает компактные детали: полное название, время, место и диапазон дат.

Пустая ячейка означает отсутствие записи. Код `С` на фоне `#EAF0F0` отличает обычную смену от пустой ячейки.

Неназначенные записи (`employeeId = null`) выводятся в дополнительной строке **«Не назначено»** после сотрудников, только если такие записи есть в выбранной неделе. Если одну дату сотрудника покрывают несколько записей, ячейка показывает первую по `start`/`sortOrder` и маркер `+N`; окно деталей перечисляет все записи этой даты.

### 6.2 Многодневные записи

Отпуск, больничный и командировка закрашивают каждую покрываемую дату диапазона `date..endDate`. Сервер выбирает записи, **пересекающие** запрошенный диапазон, поэтому отсутствие, начавшееся до понедельника, не пропадает из недели.

## 7. Данные и API

`GET /api/team/schedule?from=YYYY-MM-DD&to=YYYY-MM-DD` остаётся доступным любому авторизованному активному сотруднику и возвращает:

```ts
{
  employees: Array<{
    id: number;
    displayName: string;
    rosterOrder: number | null;
  }>;
  shifts: Shift[];
}
```

Правила ответа:

- `employees` содержит всех активных сотрудников и уже отсортирован по `rosterOrder`, затем `id`;
- `shifts` формируются через `listShiftsOverlapping`, а не `listShiftsInRange`;
- `from` и `to` обязательны, имеют строгий формат `YYYY-MM-DD`, `from <= to`, максимальный диапазон — 31 день;
- архивные сотрудники не добавляются в строки, но историческая запись с архивным/неактивным сотрудником не должна ломать ответ.

Mini-app больше не выполняет отдельный `/api/employees` только ради подписей расписания. Один ответ является источником данных для обеих вкладок.

## 8. Состояние и загрузка

Экран хранит локально:

- `mode: 'today' | 'week'`, начальное значение `today`;
- выбранную дату;
- начало выбранной недели;
- последний успешно загруженный ответ.

При изменении даты или недели запрашивается соответствующий диапазон. Устаревший ответ не может перезаписать более новый: каждый запрос получает монотонный request id, и состояние принимает только ответ последнего id.

Во время обновления уже показанные данные остаются на экране с небольшим индикатором загрузки. Стрелки временно блокируются от повторного запуска того же запроса.

Ошибка отображается рядом с расписанием с кнопкой «Повторить»; остальная навигация приложения продолжает работать.

При возврате мини-приложения из background видимый диапазон обновляется, как и остальные worker-facing данные.

## 9. Компоненты

Рекомендуемые границы:

- `TeamScreen` — состояние режима, даты, загрузки и переключения;
- `TeamViewSwitcher` — `Сегодня | Неделя`;
- `TeamTodayView` — хронологические группы выбранного дня;
- `TeamWeekGrid` — матрица `employees × 7 дней`;
- `TeamEntryDetails` — детали выбранной ячейки;
- `team-schedule.ts` — чистые функции группировки, сортировки, покрытия дат, кодов и цветовой карты;
- API client — типизированная загрузка `{ employees, shifts }`.

Чистая логика не должна находиться внутри JSX: это позволит полноценно проверить порядок, диапазоны и пустые строки без браузера.

## 10. Проверки

### Сервер

- endpoint требует `from` и `to`, отклоняет неверный/слишком длинный диапазон;
- возвращает всех активных сотрудников в порядке ростера, включая сотрудников без смен;
- не возвращает архивных сотрудников как строки;
- сохраняет неназначенные записи в `shifts`, чтобы UI мог показать строку «Не назначено»;
- возвращает многодневную запись, начавшуюся до `from`, если она пересекает диапазон;
- миграция переименовывает существующий пресет без смены `id` и сохраняет ссылки записей;
- сохранённые заголовки записей этого пресета тоже переименованы; активного пресета или пользовательского текста `Открытие` после миграции нет.

### Mini-app

- новый mount всегда открывается в режиме `Сегодня`;
- режим не читается и не записывается в persistent storage;
- timed-группы сортируются по времени, равные — по `sortOrder`;
- безвременные записи всегда находятся после хронологии;
- сотрудники внутри групп и строки недели следуют порядку ростера;
- сотрудник без смен присутствует пустой строкой в недельной матрице;
- неназначенные и несколько покрывающих одну дату записи отображаются без потери данных;
- видны ровно семь дней, корректно включая переход месяца;
- многодневные записи покрывают каждую дату пересечения;
- коды и цвета соответствуют таблице из §3;
- переключение дня/недели запрашивает правильный диапазон;
- устаревший запрос не перезаписывает свежий;
- loading, empty и error/retry состояния не ломают переключатель и навигацию;
- сетка остаётся читаемой при ширине 320 px и в обеих Telegram-темах.

## 11. Не входит в Stage 2B

- редактирование расписания работником;
- сохранение выбранной вкладки между открытиями;
- фильтры по сотрудникам или видам смен;
- поиск;
- изменение бизнес-правил обмена, баланса или напоминаний;
- изменение мобильной нижней навигации.

## 12. Критерии готовности

- При открытии «Команды» пользователь сразу видит хронологию текущего дня.
- Недельный режим вручную показывает все семь дней и всех активных сотрудников в исходном порядке ростера.
- ФИО и смены не слипаются на телефоне.
- Цвета визуально совпадают с рабочим примером и имеют текстовый код.
- «Открытие» нигде не предлагается; вместо него работает «Дежурство с 07:00».
- Навигация по датам и неделям загружает корректный диапазон без гонок.
- Все новые серверные, клиентские и responsive-проверки проходят.
