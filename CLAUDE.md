# planer-bot — правила репозитория

> Зеркало: `AGENTS.md`. Любую правку вносить **в оба файла**, иначе Claude и Codex
> разъедутся. Этот файл уточняет глобальные правила, а не повторяет их.

Telegram-бот и Mini App для командного графика: смены, дежурства, обмены, выходные,
сборы. Живая система — ей пользуется реальная команда, база одна и она в проде.

## Слои каталогов

Глобальная таблица слоёв применяется к этому репозиторию так:

| Каталог | Слой | Что это значит |
| --- | --- | --- |
| `shared/` | 1 | доменные правила. Спека + план + **TDD обязателен** |
| `server/` | 1 | API, бот, БД, миграции. Спека + план + **TDD обязателен** |
| `miniapp/`, `admin/` | 2 | лёгкая спека; логика — TDD, вёрстка — нет |
| `client/` | 1 | транспорт и контракт (появляется в треке A) — TDD обязателен |
| `ops/`, `mac/`, `.github/` | 3 | плисты, скрипты, CI. TDD **неприменим** — постусловия |
| живой сервис на iMac | 4 | сначала диагностика, потом мутация |

Пропуск TDD на слоях 3–4 — ожидаемое поведение, а не рационализация, и разрешения
на него спрашивать не нужно.

## Гейт

```bash
npm test          # 1791 тест, ~21 с
npm run typecheck # все воркспейсы
npm run lint      # biome, только правила корректности
```

Отдельный файл: `npx vitest run server/src/http/read.test.ts`.

Ничего не считается готовым без прогнанной команды с показанным выводом. «Посмотрел
код» и «должно работать» доказательством не являются.

## Правила, нарушение которых дорого

**Настоящих ФИО в репозитории быть не может.** Он публичный. Имена в тестах и доках
вымышлены — «Аня», «Игорь», «Марк». Сторож: `server/src/db/no-real-names.test.ts`.
Файл-ростер с реальными людьми не коммитится; тест против него включается переменной
`ROSTER_CSV`. Один `git add -A` из неправильного каталога — и правку придётся выносить
из истории, а не из рабочего дерева.

**Комментарий объясняет «почему», а не «что».** Так написан весь существующий код, и
это его главная ценность: комментарии в `rate-limit.ts`, `backup-db.sh`, `entry-schema.ts`
объясняют решения, которые иначе выглядели бы произвольными. Новый код пишется так же.

**Текст, который читает человек, — по-русски.** Ошибки, кнопки, сообщения бота.
Английский остаётся в именах кода.

**Один процесс обслуживает и API, и long-polling бота.** Поэтому «широкий» запрос
задел бы чат всей команды: админские отчёты и импорт ограничены по размеру тела и по
длине диапазона дат. Снимая такое ограничение, надо понимать, что снимаешь.

**База — SQLite в WAL.** Никогда не копировать её через `cp`/`rsync`: данные лежат в
`-wal`, и копия, снятая на ходу, открывается без таблиц. Единственный правильный способ —
`sqlite3 .backup`, и он уже написан в `ops/backup-db.sh`.

**Дата — командная, а не серверная.** `teamNow(config.teamTz)`, а не `new Date()`:
граница дня не должна зависеть от того, где физически находится человек или машина.

## Методология

Спеки — `docs/superpowers/specs/`, планы — `docs/superpowers/plans/`. Аудит ведётся
командой `/goal`, его состояние — `docs/audit/ledger.md`, а не в контексте диалога.

Находка про поведение, всплывшая посреди чужой работы, идёт в ledger, а не чинится
заодно: смешать две работы значит лишить обе доказательства. Гигиена (мёртвый импорт,
разъехавшееся имя типа) чинится на месте, и план правится в том же заходе.

## Ветки и коммиты

Работа идёт на ветке `feature/<тема>`, не в `main`. Сообщение коммита — по-русски, в
стиле истории: `feat(...)`, `fix(...)`, `refactor(...)`, `chore(...)`, `docs(...)`,
`test(...)`. В теле — что стало правдой и чем это доказано.
